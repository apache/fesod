任何支持社区并在 CoPDoC 任意领域工作的人都可以成为 Apache Fesod 的 PMC 成员。CoPDoC 是以下四点的缩写，用来描述我们如何不仅仅通过代码来认识到您的贡献：

- **(Co)mmunity** - 你可以通过我们的邮件列表、问题追踪器、讨论页面与社区成员互动，并分享愿景和知识。
- **(P)roject** - 需要明确的愿景和共识。
- **(Do)cumentation** - 没有它，内容只会停留在作者的头脑中。
- **(C)ode** - 没有代码，讨论就毫无意义。

Apache Fesod 社区努力追求基于功绩的原则。因此，一旦某人在 CoPDoC 的任何领域做出了足够的贡献，就有资格成为 PMC 成员的候选人，并最终被选举为 Apache Fesod 的 PMC 成员。成为 PMC 成员并不一定意味着你必须使用提交权限向代码库提交代码；它意味着你致力于 Apache Fesod 项目，并为社区的成功做出积极贡献。

## PMC 成员的要求

成为 committer 或 PMC 成员没有严格的规则。新的 PMC 成员候选人通常是积极的贡献者和社区成员。不过，如果能稍微明确一些规则，可以在一定程度上消除贡献者的疑虑，使社区更加透明、合理和公平。

### 持续的贡献

PMC 成员候选人应持续参与并为 Apache Fesod 做出大量贡献（例如修复缺陷、添加新功能、编写文档、维护问题看板、代码审查或回答社区问题）。

- 12 个月以上的活动与参与。

### 贡献的质量

- 对项目有扎实的整体理解。
- 经过充分测试、设计良好、遵循 Apache Fesod 编码规范且改动简洁的补丁。
- 组织良好、面向用户的详细文档。

### 社区参与

- 在开发邮件列表上保持积极、礼貌与尊重，并帮助指导新的贡献者和用户。
- 在项目维护的问题跟踪器上保持积极、礼貌与尊重。
- 在拉取请求审查中保持积极、礼貌与尊重。
- 即使存在分歧，也要以专业和得体的态度参与技术路线图的讨论。
- 通过撰写文章或举办活动来推广项目。

## PMC 成员的产生方式

PMC 成员的加入由 PMC 自己决定，按照 [ASF 投票规则](https://www.apache.org/foundation/voting.html) 在私有邮件列表上进行投票。[Apache PMC 指南](https://www.apache.org/dev/pmc.html) 更详细地介绍了 PMC 成员的职责和成员名单维护流程。

1. **提名候选人。** 任何 PMC 成员都可以在 <private@fesod.apache.org> 发起 `[DISCUSS]` 讨论，提名某位贡献者成为 PMC 成员。请使用候选人完整的公开姓名，而不是只用 GitHub id，并概述其在 CoPDoC 各方面的贡献。
2. **投票。** 当讨论显示多数回复者支持时，在 <private@fesod.apache.org> 发起独立的 `[VOTE]` 线程，持续一周。获得至少 3 个 +1 有效票（binding vote）且没有 -1 否决票，即为通过。
3. **公布结果并发出邀请。** 在同一列表以 `[RESULT] [VOTE]` 为主题公布结果，然后私下向候选人发出邀请，并抄送 <private@fesod.apache.org>。候选人可以私下拒绝。
4. **更新成员名单。** 候选人接受后，由 PMC Chair 使用 [Whimsy 成员名单工具](https://whimsy.apache.org/roster/committee/fesod) 将新成员加入 PMC 名单，成员名单变更会自动通知董事会。新成员会在 <dev@fesod.apache.org> 公布，并需要订阅 <private@fesod.apache.org>。

如果候选人还不是 committer，PMC 会先授予其 committer 权限；后续步骤见 [提名新 Committer](./nominate-committer.md) 和 [Onboarding](./onboarding.md)。PMC Chair 是由董事会任命的 ASF 官员，并按季度向董事会报告项目健康状况。
