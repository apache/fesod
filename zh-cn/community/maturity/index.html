Maturity

The goals of this maturity model are to describe how Apache projects operate in a concise and high-level way, and to provide a basic framework that projects may choose to use to evaluate themselves.

More details can be found in the Apache Project Maturity Model.

Status of this assessment​

This self-assessment was prepared during the incubation of Apache Fesod (Incubating).

  • Last reviewed: 2026-11-12
  • Model: Apache Project Maturity Model, version 1.4
  • Scope: the project's community practices, the published releases up to 2.1.0-incubating, and the main branch of apache/fesod at the review date. Remarks that describe a change on main state explicitly when that change is not yet part of a published release.

This is a self-assessment that guides the community; it is not a score or a graduation decision.

Maturity model assessment​

The following table is filled according to the Apache Maturity Model. Mentors and community members are welcome to comment and modify it.

Code​

CD10The project produces Open Source software for distribution to the public, at no charge.YES ✅The project source code is licensed under the Apache License 2.0.
CD20Anyone can easily discover and access the project's code.YES ✅The official website links to the project's GitHub repository from its navigation bar.

Git history and pull requests record authorship and review, and third-party contributions follow the contributing guidelines.

Licenses and Copyright​

IDDescriptionStatusRemark
LC10The Apache License, version 2.0, covers the released code.YES ✅The project is licensed under the Apache License 2.0. Bundled third-party code retains its applicable license and attribution notices.
LC20Libraries that are mandatory dependencies of the project's code do not create more restrictions than the Apache License does.YES ✅Mandatory dependencies are declared in the module POMs, for example fesod-sheet/pom.xml. As reviewed on main at the review date, the resolved runtime dependencies of fesod-sheet (Apache POI, Apache Commons, Apache XMLBeans, Log4j API, Ehcache and SparseBitSet under the Apache License 2.0; SLF4J API under the MIT License; curvesapi under the BSD 3-Clause License) are all in ASF Category A. The Spring Framework classes relocated into fesod-shaded, including code derived from ASM and CGLIB, are documented in that module's LICENSE and NOTICE.
LC30The libraries mentioned in LC20 are available as Open Source software.YES ✅All mandatory dependencies listed in LC20 are Open Source software published under licenses in ASF Category A. The release verification guide requires reviewers to check the LICENSE and NOTICE files of each release candidate.
LC40Committers are bound by an Individual Contributor Agreement (the "Apache iCLA") that defines which code they may commit and how they need to identify code that is not their own.YES ✅Every committer has a signed Apache iCLA on file, which is a prerequisite for an ASF committer account.
LC50The project clearly defines and documents the copyright ownership of everything that the project produces.YES ✅Copyright and third-party attribution are documented in NOTICE and license notices. Following a review of source provenance and copyright attribution, attribution was corrected and the third-party notice carried by Apache POI's DataFormatter was restored on main (#1323, #1330, #1331; tracked in #1322). These changes are not yet included in a published release, and final confirmation is pending in LEGAL-737.

Releases​

IDDescriptionStatusRemark
RE10Releases consist of source code, distributed using standard and open archive formats that are expected to stay readable in the long term.YES ✅Source releases are distributed as .tar.gz archives via dist.apache.org and linked from the download page. The download page records four releases during incubation, from 2.0.0-incubating (2026-01-21) to 2.1.0-incubating (2026-10-07).
RE20The project's PMC (Project Management Committee, see CS10) approves each software release in order to make the release an act of the Foundation.YES ✅Releases are voted on via dev@fesod.apache.org and approved by the IPMC via general@incubator.apache.org. Each stage requires at least three binding +1 votes and more binding +1 than -1 votes; only IPMC votes are binding for ASF release approval. See the 2.1.0 RC7 IPMC vote.
RE30Releases are signed and/or distributed along with digests that anyone can reliably use to validate the downloaded archives.YES ✅All source releases are signed and published with .asc signatures and .sha512 checksums. The KEYS file is available, and the download page explains how to verify signatures and checksums.
RE40The project can distribute convenience binaries alongside source code, but they are not Apache Releases, they are provided with no guarantee.YES ✅Only the voted source archives, distributed via dist.apache.org and the ASF archive, are Apache Releases. The corresponding binary artifacts on Maven Central, such as org.apache.fesod:fesod-sheet, are convenience binaries and are not Apache Releases.
RE50The project documents a repeatable release process so that someone new to the project can independently generate the complete set of artifacts required for a release.YES ✅The release guide documents how to prepare, vote on, and publish an Apache Fesod (Incubating) release.

Quality​

IDDescriptionStatusRemark
QU10The project is open and honest about the quality of its code. Various levels of quality and maturity for various modules are natural and acceptable as long as they are clearly communicated.YES ✅The security model documents the library's known limits, including that parsing is not a sandbox, that untrusted documents may consume substantial CPU, memory or disk, and how temporary files, caches and password-protected files are handled. Known issues are tracked publicly in GitHub issues, and incompatible changes are listed in the release notes.
QU20The project puts a very high priority on producing secure software.YES ✅The security model defines trust boundaries, deployment responsibilities and supported versions; security fixes are provided on the most recent release line. Security reports are handled privately according to the security policy, with fixes and advisories coordinated through the ASF security process.
QU30The project provides a well-documented, secure and private channel to report security issues, along with a documented way of responding to them.YES ✅The security page directs reports privately to security@apache.org, and the security model documents how reports are handled, fixed and disclosed. Past advisories, such as CVE-2026-49328 and CVE-2026-107460, are published on the project blog.
QU40The project puts a high priority on backwards compatibility and aims to document any incompatible changes and provide tools and documentation to help users transition to new features.YES ✅The project prioritizes backwards compatibility and documents incompatible changes in release notes and the migration guide. For example, the CVE-2026-107460 advisory explains that 2.1.0-incubating disables remote URL image fetching by default as a security fix. An OpenRewrite recipe automates updating dependencies, class names and package imports when migrating from FastExcel.
QU50The project strives to respond to documented bug reports in a timely manner.YES ✅The community responds to bug reports and follows through on fixes. For example, issue #828 received a reproduction response on the day it was reported, followed by an update on the 2.0.1-incubating fix.

Community​

IDDescriptionStatusRemark
CO10The project has a well-known homepage that points to all the information required to operate according to this maturity model.YES ✅The official website points to the information this maturity model requires, including downloads, documentation, community and contribution guides, security, and this assessment.
CO20The community welcomes contributions from anyone who acts in good faith and in a respectful manner, and who adds value to the project.YES ✅The general contributing guide and the website guides for code and documentation contributions explain how anyone can take part.
CO30Contributions include source code, documentation, constructive bug reports, constructive discussions, marketing and generally anything that adds value to the project.YES ✅Both code and non-code contributions are welcome, such as documentation, translations, bug reports, discussions and blog posts. The documentation contribution guide covers non-code contributions.
CO40The community strives to be meritocratic and gives more rights and responsibilities to contributors who, over time, add value to the project.YES ✅During incubation, the community has added 3 new committers, including 2 who subsequently joined the PPMC. See the incubation status and team pages (as of 2026-11-10).
CO50The project documents how contributors can earn more rights such as commit access or decision power, and applies these principles consistently.YES ✅The requirements for becoming a committer and becoming a PPMC member are documented, together with the nomination process that PPMC members follow.
CO60The community operates based on consensus of its members (see CS10) who have decision power. Dictators, benevolent or not, are not welcome in Apache projects.YES ✅Decisions are made through community discussion and consensus, using formal votes where required. The CI approval discussion and issue #1009 show discussion, agreement, and follow-through.
CO70The project strives to answer user questions in a timely manner.YES ✅The community answers questions through dev@fesod.apache.org, GitHub issues, and discussions. For example, issue #828 received an initial response within minutes and subsequent updates.

Consensus Building​

IDDescriptionStatusRemark
CS10The project maintains a public list of its contributors who have decision power. The project's PMC (Project Management Committee) consists of those contributors.YES ✅The team page lists all PPMC members and committers, and links to the ASF committer authorization-group listing.
CS20Decisions require a consensus among PMC members and are documented on the project's main communications channel. The PMC takes community opinions into account, but the PMC has the final word.YES ✅The PPMC builds consensus while considering community input, and records decisions on the mailing lists. See the CI approval discussion and conclusion. Voting requirements depend on the type of decision.
CS30The project uses documented voting rules to build consensus when discussion is not sufficient.YES ✅The project follows the ASF voting rules and its documented release process. The 2.0.0 RC3 vote result records binding and non-binding votes separately.
CS40In Apache projects, vetoes are only valid for code commits. The person exercising the veto must justify it with a technical explanation, as per the Apache voting rules defined in CS30.YES ✅Under the ASF voting rules, a code-commit veto requires technical justification and cannot be overridden by a majority vote. Release votes are not subject to veto.
CS50All "important" discussions happen asynchronously in written form on the project's main communications channel. Offline, face-to-face or private discussions that affect the project are also documented on that channel.YES ✅Important discussions and conclusions are recorded asynchronously on dev@fesod.apache.org. For example, issue #1009 directs a proposed CI policy change to the mailing list for consensus before implementation. Personnel and undisclosed security matters use the appropriate private channels.

Independence​

IDDescriptionStatusRemark
IN10The project is independent from any corporate or organizational influence.YES ✅Apache Fesod (Incubating) is governed by its community. Project decisions are made through community consensus, and no company has unilateral decision-making authority.
IN20Contributors act as themselves, not as representatives of a corporation or organization.YES ✅The contributors act on their own initiative without representing a corporation or organization.

The homepage marks the first prominent mention as "Apache Fesod™ (Incubating)", and the website footer states that Apache Fesod, Fesod, and the Fesod logo are trademarks of The Apache Software Foundation, alongside the general ASF trademark attribution.

Incubation is required of all newly accepted projects until a further review indicates that the infrastructure, communications, and decision making process have stabilized in a manner consistent with other successful ASF projects. While incubation status is not necessarily a reflection of the completeness or stability of the code, it does indicate that the project has yet to be fully endorsed by the ASF.
